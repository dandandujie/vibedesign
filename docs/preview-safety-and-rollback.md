# Project V2 预览安全与回滚

Project V2 的旧项目迁移采用“先备份、再复制”的方式：旧 `projects.json` 不会被迁移器覆盖，迁移后的设计项目写入用户另行选择的目录。首页右上角的“预览安全”会显示本机实际源文件、迁移备份和当前验证状态。

## 停止使用预览模型

1. 退出 VibeDesign，避免应用仍在写入本地数据。
2. 保留已经生成的 Project V2 项目目录；它们是可携带的前端项目，从最近项目移除不会删除磁盘文件。
3. 重新启动 VibeDesign，继续使用首页“扩展项目”中的旧项目。
4. 确认旧项目正常后，再自行归档或删除不需要的迁移项目目录。

这条路径不需要恢复备份，因为迁移不会修改旧源文件。

## 旧源文件损坏或被误改

1. 退出 VibeDesign。
2. 在“预览安全”中复制“旧数据”和“迁移备份”两个路径。
3. 先为当前旧源文件再做一份副本，不直接删除。
4. 将迁移备份复制到旧源文件位置并恢复原文件名。
5. 启动 VibeDesign，检查旧项目数量和内容。

“旧数据在迁移后发生过变化”只表示源文件内容已不同于迁移时快照，可能是用户后来正常编辑旧项目；它不表示备份损坏，也不应触发自动覆盖。

## 反馈包

“预览安全”中的反馈表单会在用户选择的目录生成 `vibedesign-preview-feedback-*.json`。文件不会自动上传，发送前可以使用任意文本编辑器检查。

反馈包包含：

- 应用版本、操作系统和架构；
- 项目、页面、流程、缺失资产和迁移结果的汇总数量；
- 用户主动填写的问题概述、复现步骤、预期结果和实际结果。

反馈包默认不包含项目名称与 ID、任何本地路径、页面源码、视觉资源、提示词、聊天记录、模型配置、API Key 或其他凭据。用户在表单中主动填写的文字会原样保留，因此仍应在发送前自行检查。
