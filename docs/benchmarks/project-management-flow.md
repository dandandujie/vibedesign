# 固定基准：轻量项目管理 Web 应用

## 用途

本基准用于验证 Project V2 的完整闭环，而不是展示一次性视觉效果。所有存储、生成、编辑、模型适配和验证变更都应使用同一基准检查回归。

## 固定需求

设计一个面向小型创意团队的轻量项目管理 Web 应用。新用户需要从空状态创建第一个项目，进入项目详情后创建第一个任务，并立即看到列表和统计更新。

目标视口：

- 桌面：1440 × 900
- 手机：390 × 844

设计约束：

- 使用项目级颜色、排版、间距、圆角和动效令牌。
- 按钮、表单字段、导航、卡片和反馈模式必须复用。
- 使用本地模拟数据，不接入后端。
- 不依赖无法打包的远程图片或字体。

## 页面

### 仪表盘

- 初始显示明确的项目空状态。
- 提供“新建项目”主操作。
- 创建成功后显示项目卡片和项目数量统计。

### 新建项目

- 包含项目名称和简短描述。
- 空名称提交时显示与字段关联的错误信息。
- 正确提交时显示进行中反馈，随后进入项目详情。

### 项目详情

- 显示项目名称、描述和任务统计。
- 初始显示任务空状态。
- 可以创建第一个任务。
- 创建后任务列表与统计同步更新，并显示成功反馈。

## 核心体验流程

```text
打开空状态仪表盘
→ 点击“新建项目”
→ 空表单提交并看到校验错误
→ 输入项目名称“网站改版”
→ 提交并看到进行中反馈
→ 进入“网站改版”项目详情
→ 点击“新建任务”
→ 创建任务“梳理首页信息架构”
→ 任务出现在列表中
→ 项目任务统计从 0 更新为 1
```

## 必须覆盖的状态

- 仪表盘空状态
- 表单默认状态
- 表单校验错误
- 提交进行中
- 项目创建成功
- 任务空状态
- 任务创建成功
- 操作成功反馈
- 桌面与手机响应式布局

## 自动验证

验证优先使用可访问角色、可见名称和表单标签定位元素；稳定的 `data-vd-id` 只作为无法使用语义定位时的后备。

硬性断言：

- 所有页面均可直接打开。
- 核心流程中的跳转和交互可完成。
- 表单错误与对应字段建立可访问关联。
- 成功反馈可被辅助技术感知。
- 无未处理页面错误或控制台错误。
- 无失效本地资源和死链接。
- 两个目标视口无明显水平溢出、遮挡或不可操作控件。
- 修改共享令牌后，三个页面仍可渲染且核心流程通过。
- 修改项目详情页局部文案时，其他页面文件不发生变化。

## 手动设计评审

- 页面之间具有一致的视觉层级和密度。
- 主操作、次操作和危险操作易于区分。
- 空状态能够解释现状并引导下一步。
- 错误、进行中和成功状态不会造成跳变或含糊反馈。
- 手机视口不是简单缩小桌面布局。
- 不存在明显随机图标、一次性颜色和互相冲突的圆角。
- 设计没有依赖与需求无关的装饰性复杂度。

## 交付验证

- 导出到一个干净目录。
- 按导出说明启动项目。
- 不运行 VibeDesign 时仍能完成核心体验流程。
- Handoff Bundle 包含页面、体验流程、设计令牌、资产说明和最近验证结果。

## 通过条件

只有当全部硬性断言通过、手动设计评审被用户接受且导出验证成功时，这条体验流程才标记为完成。
